= Model Deployment and Metrics
:navtitle: Model Deployment and Metrics

You open a chat interface, type a question, and hit Enter.
There is a brief pause -- maybe a second or two -- and then text starts streaming in, word by word.
Have you ever noticed that the pause before the first word is always longer than the gaps between subsequent words?
That is not a UI quirk.
That pause is the model doing fundamentally different work than the streaming that follows.

Understanding that difference is the key to understanding every inference metric you will monitor in this course.

In the previous chapter, you enabled User Workload Monitoring and verified that GPU hardware metrics flow into Prometheus.
But you have no application-level metrics yet because there is no model running.
This chapter deploys a model and completes the three-layer metrics pipeline.

== Chapter Objectives

By the end of this chapter, you will be able to:

* Explain the prefill and decode phases of LLM inference and how they map to TTFT and TPOT metrics
* Describe why the KV cache limits concurrent request capacity on a memory-constrained GPU
* Identify the four categories of vLLM metrics (latency, throughput, saturation, diagnostic) and their Prometheus types
* Deploy a model on RHOAI 3.4 using the three-resource model (HardwareProfile, ServingRuntime, InferenceService)
* Verify that all three layers of observability -- container, GPU, and inference metrics -- are flowing into Prometheus
