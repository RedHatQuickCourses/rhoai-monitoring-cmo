== Introduction

Imagine you are an AI platform engineer.
Your team deployed a large language model on OpenShift AI to power an internal chatbot.
On Monday morning, users start complaining: "The chatbot is really slow today."
Your manager asks: "Is it the model? The GPU? The network? Are we getting more traffic than usual?"

You open the OpenShift console and see the pod is Running, CPU usage is 12%, memory looks fine.
Everything looks green.
But users are still waiting 30 seconds for a response.

The answer is that *traditional Kubernetes metrics cannot tell you what is happening inside an AI inference workload*.
The pod is running, but the GPU's KV cache is full, requests are queuing, and the model is bottlenecked on GPU memory.
You would never know this from `cpu_usage` and `memory_working_set`.

This is why AI model serving requires a different observability strategy -- and that is what this course is about.
